## 1. 指标设计框架

为了衡量“PM知识库智能体”系统的健康度、检索效能以及对用户学习/面试场景的赋能价值，设计了如下指标框架。由于系统为本地部署，指标采集可使用本地轻量日志记录，并在关于页面中以仪表盘形式可视化展示。

## 3. 指标定义与采集说明

### 3.1 北极星指标 (North Star Metric)
- **定义**：**单次会话有效召回率 (Session Recall Rate, SRR)**
  - 指在单次知识库问答会话（至少包含3轮对话）中，用户未点击“重试”且引用的原始笔记切片与用户意图匹配度评分为“高”的比例。
- **为什么选它**：作为垂直知识库，用户最核心的需求是“精准召回自己学过的知识点”。若召回不准或幻觉严重，用户就会频繁点击重试，这意味着检索失效。SRR 综合反映了 RAG 系统底层切片、向量检索与 Prompt 工程的整体效能。
- **采集方式**：本地日志记录用户的 `Retry` 按钮点击事件；在开发测试阶段，采用黄金测试集（Golden Dataset）人工标注意图与召回结果的重合度。

---

### 3.2 L1 层：系统与检索质量指标

| 指标名称 | 定义与计算公式 | 理想区间 | 采集方式 | 产品优化策略 |
|---------|--------------|---------|---------|-------------|
| **完整响应时间** | 从提交请求到后端返回完整 JSON 的耗时。 | P95 < 10s | 后端 API 计时器。 | 分别检查检索、模型供应商和网络耗时；当前版本不是 SSE，不能使用首字时间口径。 |
| **检索有结果率** | 语义或关键词查询返回至少 1 条结果的查询占比，按模式分别统计。 | 黄金测试集 > 95% | 后端检索日志 + 黄金测试集。 | 分析无结果查询、笔记覆盖与切片质量；当前两个模式独立运行，不使用 BM25/RRF 融合权重。 |
| **引用源点击率 (Reference CTR)** | 用户在看完 AI 回答后，点击折叠栏查看“原始笔记来源路径”的比例。 | > 40% | 前端 UI 埋点日志。 | 较高的 CTR 证明用户正在利用本系统作为“Obsidian 的导航入口”，实现了知识回溯。 |
| **重试与打回率 (Regeneration Rate)** | 用户单次会话中点击“重新生成”的平均次数。 | < 0.2次/会话 | 前端 UI 埋点日志。 | 若偏高，说明 Prompt 约束不够或召回切片不全，需调整 Prompt 模板。 |

---

### 3.3 L2 层：用户体验与面试赋能指标

| 指标名称 | 定义与计算公式 | 理想区间 | 采集方式 | 产品优化策略 |
|---------|--------------|---------|---------|-------------|
| **模拟面试完成率 (Completion Rate)** | 开始模拟面试并最终生成“STAR评估报告”的会话比例。 | > 70% | 后端会话状态机记录。 | 若中途流失率高，说明单次模拟题量过大（如超过5题），应缩短为3题一轮。 |
| **STAR 得分成长率 (Growth Rate)** | 用户在同一个面试主题下，第N次模拟相较于第1次模拟的分数提升比例。 | > 15% (练习10次后) | 数据库中历史评估报告的分数对比。 | 提供更具体的“差分分析”，指出具体是 S、T、A、R 哪个维度的得分阻碍了总体成长。 |
| **平均答题字数** | 用户在模拟面试输入框中输入的平均字符数。 | 150 - 400字 | 前端输入框字符统计。 | 字数太少（< 50字）说明候选人未展开叙述；字数太多（> 800字）说明缺乏凝练。通过 UI 进度条进行字数友好提示。 |

## 4. 指标采集落地实现 (v1.1.0)

为了支撑核心指标的真实呈现，系统在 v1.1.0 中实现了轻量化的运行时指标数据端点：

### 4.1 后端指标收集 (GET `/api/v1/metrics`)
* **ChromaDB 索引容量 (L2)**：直接调用 `collection.count()`，实时获取向量库当前切片容量。
* **累计问答与面试次数 (L1)**：在 FastAPI 服务的 `app.state` 周期中挂载 `total_queries` 计数器，当收到 `/qa/ask` 与 `/interview/evaluate` 请求时递增。
* **真实 vs 演示 LLM 占比**：在后台统计 `live_queries` (Gemini 真实问答调用) 和 `mock_queries` (因无 Key 或 API 异常回退的 Mock 调用) 计数。

### 4.2 前端实时仪表盘展示
* 首页工作台最下方挂载了「系统运行指标」实时看板，通过定期/首屏发起 `/metrics` API 请求获取数据。
* 用纯 CSS 渲染可视化的「LLM 调用配比条 (真实 vs 演示)」，用直观的色条展示当前环境的大模型连接状态与占比。
