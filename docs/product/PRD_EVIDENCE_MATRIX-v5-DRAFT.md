# 个人知识工作台 PRD v5 需求与证据矩阵（草案）

> 对应需求：[PRD v5 草案](PRD-v5-DRAFT.md) · [v2 信息架构](../design/V2_INFORMATION_ARCHITECTURE.md) · [可运行原型说明](../design/V2_PROTOTYPE_SPEC.md) · 盘点日期：2026-08-26 · 文档版本：`v5.0-draft.5` · 状态：设计基线已验收；v2 实现未开始

> **文档边界：**本文追踪 v2 需求从何而来、由什么设计和架构承接、用什么指标验收。它不把计划能力写成已实现，也不替代代码、测试、原型或历史证据。v1.x 当前事实仍以 [PRD v4](PRD.md)和 [v1.6 归档基线](../archive/baselines/2026-08-24-v1.6.0-rc.1/BASELINE.md)为准。

## 1. 状态与证据图例

### 1.1 证据等级

| 等级 | 含义 | 可支持的结论 |
|---|---|---|
| E1 | 外部个人用户的真实行为、留存、付费或拒绝数据 | 用户价值、市场与商业判断 |
| E2 | 当前代码、自动化测试、冻结评测集和可复现环境 | 实现状态、质量与性能 |
| E3 | 项目所有者长期使用、访谈陈述或内部 Dogfood | 问题假设、方向和内部优先级 |
| E4 | 原型、需求推演、竞品桌研和设计评审 | 目标设计、风险和待验证假设 |

当前项目没有足够的 v2 E1 证据。多空间、多格式、原生反链、图谱价值和 Agent 效率均不得写成已被外部市场验证。

### 1.2 交付状态

| 状态 | 定义 |
|---|---|
| `V1-E2` | v1.x 存在可复现实现证据，但对象或体验不足以满足 v2 |
| `DECIDED` | 产品方向已由项目所有者确认 |
| `HYPOTHESIS` | 外部频率、价值、留存或付费仍待验证 |
| `DESIGN-PENDING` | 需要架构/原型决策，尚不能进入实现 |
| `NOT-STARTED` | v2 实现未开始 |
| `FUTURE` | 非 v2 验收，不进入近期实现 |

### 1.3 追踪规则

- 每个 P0/P1 功能必须同时具备：市场需求、用户旅程、指标、原型、架构责任、实现状态和验收证据；
- “当前有类似页面”不等于 v2 需求已实现；必须核对数据对象、边界、异常和验收；
- 原型和架构未通过评审的需求不能进入开发；
- 自动化测试通过不能替代 E1 用户价值证据；
- PM 模板只能映射通用能力，不得反向定义所有用户的主旅程。

## 6. v1.x 基线如何承接

| v1.x 能力/证据 | v2 可复用部分 | 不可直接继承的结论 | 处理方式 |
|---|---|---|---|
| 单一 `NOTES_DIR` 与 Markdown 索引 | 文件扫描、Markdown 解析和部分索引代码 | 不能证明多空间、多来源或外部自助成功 | 封装为 Source/Parser 适配器，并通过迁移导入默认空间 |
| 语义与子串检索 | 查询接口、向量或文本召回经验 | 不能证明混合检索质量或规模性能 | 先建立冻结基线，再决定融合与重排 |
| 来源问答和编号引用 | 有证据回答的交互基础 | 不能证明跨格式锚点准确和范围隔离 | 统一 Citation/Anchor 对象并补评测 |
| Markdown 预览和本地图片 | 阅读器与受限资产读取经验 | 不能证明 PDF、表格、图片区域引用 | 建格式适配器和统一 Block/Asset 模型 |
| 目录/笔记知识图 | 可视化和大图降级经验 | 不能把启发式连线迁移为事实关系 | 旧图只作历史结构；新图从证据关系重建 |
| 单轮 PM 面试 | 提问、反馈、历史和导出经验 | 不能证明通用 Agent、多轮或场景模板复用 | 降为可选模板实例，先接通通用工具和行动对象 |
| local/live/fallback/demo | 模式披露与降级经验 | 不能证明空间级策略和外发最小化 | 设计统一 Model/Privacy Policy 和审计 |
| 现有测试与验收 | 回归基线和历史质量事实 | 不能证明 v2 新对象、新格式和外部价值 | 保留 v1 回归，另建 v2 测试策略与 E1 验证 |

## 7. 需求就绪门槛（Definition of Ready）

任一 v2 功能进入实现前必须满足：

- [ ] PRD ID、目标用户任务和非目标清楚；
- [ ] 对应 MR、用户旅程和指标可追溯；
- [ ] 桌面/移动及空、加载、错误和恢复原型通过评审；
- [ ] 数据对象、授权范围、版本和迁移责任明确；
- [ ] 隐私、外发、写入和删除风险已分级；
- [ ] 验收样本、自动测试、性能口径和发布护栏已定义；
- [ ] v1.x 兼容、迁移和回滚方案存在；
- [ ] 当前状态没有被误写为“已实现”。

## 8. 交付完成门槛（Definition of Done）

- [ ] 功能验收、错误恢复和权限边界通过；
- [ ] 代码、测试、原型和文档使用同一对象与需求 ID；
- [ ] 指标事件按隐私规范持久化，并能复算；
- [ ] 桌面和移动约定范围通过可访问性检查；
- [ ] 性能在冻结设备与数据集上报告 P50/P95；
- [ ] 迁移、撤销、备份或回滚按风险完成演练；
- [ ] 交付事实写入 `docs/delivery/`，不只更新路线图；
- [ ] E2 工程结果与 E1 用户结果分别陈述。
