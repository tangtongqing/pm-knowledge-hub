# ADR-0002：支持原位连接与工作区管理副本两种来源模式

## 状态

Proposed — 2026-08-24

## 背景

用户既希望直接使用本地文件夹和现有工具，也希望上传/导入单个文件交给系统统一管理。只支持原位连接会限制上传和 Agent 编辑；只支持复制会增加占用、重复和数据所有权疑问。

## 方案比较

| 方案 | 优点 | 缺点 | 复杂度 | 适用条件 |
|---|---|---|---|---|
| 仅原位连接 | 不迁移、不重复；适合现有目录 | 来源失联；不能安全编辑；上传体验弱 | 低 | v1.x 兼容和只读知识库 |
| 仅复制进入工作区 | 数据边界统一；便于版本和 Agent 管理 | 占空间；用户担心锁定和重复 | 中 | 用户愿意显式迁移资料 |
| 两种模式统一建模 | 覆盖现有目录和导入文件；选择透明 | 删除、同步、冲突和 UI 更复杂 | 中 | v2 目标 |

## 决策

Source 模型从第一版区分：

- `reference`：连接原位，系统只读；原文件始终是内容来源；
- `managed_copy`：用户明确选择复制到工作区，副本由工作区管理，可在风险规则内被用户或 Agent 修改。

两种模式使用同一 Document/Version/Block 模型。是否在 M1 UI 同时交付两种模式由产品评审决定，但数据模型和接口不能把单一模式写死。

## 规则

1. 导入前展示模式、目标空间、磁盘占用、联网/OCR 和删除含义；
2. `reference` 的 SourceAuthorization 永远不授予写权限；
3. `managed_copy` 写入只发生在工作区数据根，不能覆盖原选择文件；
4. “解除连接”“删除索引”“删除管理副本”“打开/删除原文件”是不同命令；
5. Source 失联只改变 availability，保留最后可用 DocumentVersion；
6. 切换模式必须走显式复制/导出流程，不能只改字段；
7. 本地绝对路径只保存在后端私有 locator，不进入 API、指标和公开日志。

## 理由

- 满足“不依赖 Obsidian、可反链回本地文件”和“用户导入文件”两个共同需求；
- 允许 v1.x `NOTES_DIR` 以只读 reference 平滑迁移；
- 为 Agent 安全提供清晰边界：只能修改 managed copy 或系统元数据；
- 用户可逐来源选择，不必一次迁移全部资料。

## 接受的取舍

- UI 和删除语义比单一模式复杂；
- managed copy 产生额外磁盘占用和版本管理；
- reference 需要处理移动、权限丢失和外部修改。

## 缓解

- 导入预览明确模式差异；
- SourceItem 使用指纹和路径历史帮助重定位；
- 数据设置分别显示原文件、副本、索引和缓存；
- M1 可以先开放 reference UI，但必须用同一 Source mode 字段和接口。

## 复审触发器

- 外部用户无法理解两种模式且持续误删/重复；
- managed copy 使用率极低、维护成本显著；
- 原位连接的权限/移动问题导致主要激活失败；
- 未来云同步或团队共享改变来源所有权模型。
