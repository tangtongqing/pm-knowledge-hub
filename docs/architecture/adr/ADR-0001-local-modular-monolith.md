# ADR-0001：采用本地模块化单体

## 状态

Proposed — 2026-08-24

## 背景

v1.x 使用 Next.js 前端和 FastAPI 后端，面向单个本地用户。v2 会增加多空间、多格式、持久任务、检索、关系和 Agent，但设计规模仍约为 10 个空间、10,000 文档、100,000 内容块，当前由单人或小规模团队维护，不需要独立扩缩容或多人实时协作。

## 方案比较

| 方案 | 优点 | 缺点 | 复杂度 | 适用条件 |
|---|---|---|---|---|
| 继续无模块单体 | 修改快 | 路由、存储和业务规则继续耦合，难以迁移 | 低/短期，高/长期 | 只做 v1 缺陷修复 |
| 模块化单体 | 保留当前栈；边界清楚；同进程事务和调试简单 | 需要建立模块纪律；不能独立扩容 | 中 | 当前 v2 |
| 微服务 | 独立部署和扩容 | 网络、认证、消息、部署和一致性成本高 | 高 | 团队 >10 且有独立扩缩容证据 |
| 单进程桌面重写 | 打包体验可能更统一 | 重写前后端和生态，迁移风险大 | 高 | 现有两进程成为主要激活阻塞后 |

## 决策

保留 Next.js + FastAPI 两个本地进程；FastAPI 内部采用模块化单体。模块通过应用服务/端口交互，SQLite 事务保留在单进程边界内。部署打包延后到 M5 决定。

首批模块：Workspace & Catalog、Ingestion & Jobs、Retrieval & Citation、Knowledge & Graph、Agent Runtime、Optional Templates、Policy & Privacy、Metrics & Evaluation。

## 理由

1. 满足当前规模和单人维护约束；
2. 可以渐进复用 v1.x FastAPI、parser、Chroma 和 Next.js 页面；
3. 导入、文档版本、链接和 Agent 审计需要本地事务，一体化更可靠；
4. 模块端口足以提供未来替换解析器、向量库和模型的能力；
5. 团队、多租户和独立扩容尚无证据，不值得承担分布式复杂度。

## 接受的取舍

- 后端模块不能独立扩容或故障隔离；
- 模块边界依赖代码审查和测试，而不是进程强制；
- Next.js 与 FastAPI 两进程的启动体验暂时保留。

## 缓解

- 禁止跨模块直接修改内部表；
- 为公开应用服务和端口建立契约测试；
- 长任务使用持久 Job 和有限并发 Worker；
- 通过本地启动器和健康检查降低两进程摩擦。

## 影响

- 不创建 Kubernetes、服务发现、Redis、Kafka 或独立认证服务；
- Agent 工具调用应用服务，而不是内部数据库或系统命令；
- 模块可在未来有证据时抽离，但当前 API 不为假想微服务过度抽象。

## 复审触发器

- 后端维护团队超过 10 人且模块需要独立发布；
- 多用户云端部署获得批准并存在独立扩缩容需求；
- 长任务必须与 API 进程资源隔离，单机 Worker 无法满足；
- 两进程安装/升级成为外部用户的主要激活阻塞。
