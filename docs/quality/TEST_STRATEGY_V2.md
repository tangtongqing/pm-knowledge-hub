# 个人知识工作台 v2 测试策略（草案）

> 对应需求：[PRD v5 草案](../product/PRD-v5-DRAFT.md) · [指标体系](../product/METRICS-v2-DRAFT.md) · [目标架构](../architecture/TARGET_ARCHITECTURE.md) · [数据模型](../architecture/DATA_MODEL.md) · [迁移计划](../architecture/MIGRATION_PLAN.md) · 文档版本：`v1.0-draft.1` · 更新日期：2026-08-26 · 状态：待验收

> **结论先行：**v2 不能沿用“页面能打开、接口返回 200、模型能回答”作为主要质量证明。测试必须围绕空间隔离、原文件安全、稳定锚点、检索证据、关系可解释、Agent 受控和迁移可回滚建立可重复证据。本文件是目标质量合同，不代表 v2 功能或测试代码已经实现。

## 1. 目的与适用范围

本策略回答五个问题：

1. 哪些失败会阻止 v2 进入下一里程碑或发布；
2. `F-01`～`F-11` 分别由哪些测试层和冻结样本验证；
3. 如何区分单元/集成/端到端工程证据（E2）与真实用户价值证据（E1）；
4. 如何报告格式、检索、图谱、Agent、迁移、性能和可访问性质量；
5. 实现开始后，哪些测试必须进入提交、主分支、里程碑和发布门禁。

适用对象：产品负责人、研发、测试、设计评审者和后续自动化执行者。

不在本策略内：

- 不把 v2 原型浏览器检查写成正式前端测试；
- 不把 Mock 模型通过写成外部模型质量已验证；
- 不定义团队成员、角色、共享空间或多租户测试；
- 不要求 M1 一次实现 M2/M3 全部套件，但数据和接口不能阻止后续补齐；
- 不使用私人知识库正文、绝对路径、密钥或真实身份信息作为仓库测试夹具。

## 2. 当前基线与差距

### 2.1 可复用的 v1.x 资产

| 资产 | 当前事实 | v2 如何承接 |
|---|---|---|
| 后端自动化 | `backend/tests/` 下 7 个 pytest 模块，覆盖解析、切块、向量、API、模型适配、基础安全和现有 Agent | 保留为回归套件；新增 v2 对象、版本、空间、任务和安全测试，不改写为 v2 证据 |
| 后端运行入口 | `backend/run_tests.py` 可在离线模型环境执行 pytest | 继续作为本地入口；实现阶段补 marker、覆盖率和分层命令 |
| 前端质量 | ESLint、TypeScript/Next.js production build 和历史 Playwright 人工复核 | 新增组件/路由测试和可重复浏览器 E2E；历史截图只作 v1 证据 |
| 系统验收 | [ACCEPTANCE.md](ACCEPTANCE.md) 和历史 Web 黑盒报告 | 冻结为 v1.x 回归依据，不直接添加 v2 计划状态 |
| 迁移思路 | [迁移计划](../architecture/MIGRATION_PLAN.md) 已定义影子迁移、双轨核验和回滚 | 转化为可自动执行的迁移夹具、故障注入和报告契约 |

### 2.2 当前缺口

- 没有 Workspace/Space/Collection/Source/Version/Block 的自动化契约测试；
- 没有 PDF、表格、图片等格式的版本化 Golden samples；
- 没有跨空间同名内容、越权查询和范围泄漏样本；
- 没有锚点在编辑、重命名、移动和版本变化后的重定位测试；
- 没有 Link/Backlink、typed Relation、证据和建议状态的一致性测试；
- 没有冻结检索查询集、相关性标注、无答案样本和可复算排名报告；
- 没有 Agent 计划版本、部分批准、幂等、撤销、提示注入和越权故障测试；
- 没有持久 Job 在重启、磁盘不足、模型失败和局部失败后的恢复测试；
- 没有前端自动化、CI 工作流、性能参考设备和容量数据生成器；
- 没有把 E2 工程指标和 E1 外部用户结果分开的统一报告模板。

## 3. 质量原则

1. **安全护栏优先于平均通过率：**一次未确认写入、越权访问或原文件破坏即可否决发布；
2. **事实库与投影分开验证：**SQLite 事实正确、FTS/向量/图谱投影可重建，两类断言不能混为一类；
3. **锚点必须打开验证：**仅校验字符串格式不算引用正确，必须打开到目标版本和具体位置；
4. **范围是每条查询和操作的输入：**测试必须同时断言返回了什么和绝不应返回什么；
5. **格式按能力等级验收：**发现文件、解析、浏览、检索、引用、更新和原文回跳逐项报告；
6. **失败是产品状态：**部分成功、重试、跳过、恢复和降级必须有可观察结果；
7. **关系必须有证据：**结构边、显式链接、确认关系和建议关系分别断言，不能只统计节点/边数量；
8. **Agent 的执行器不信任模型：**授权、版本、风险、幂等和范围由确定性代码重新校验；
9. **冻结样本可复算：**数据、标注、配置、设备、模型和代码版本进入报告；
10. **E2 不冒充 E1：**自动化通过证明工程行为，不能证明外部用户愿意使用或付费。

## 4. 发布否决项

以下任一项在目标里程碑范围内发生即为 `BLOCK`，不能用总通过率抵消：

| ID | 否决事件 | 对应指标 |
|---|---|---|
| QG-01 | 未选择或未授权空间的内容被搜索、问答、图谱或 Agent 返回 | `RET-05`、`AGT-06` |
| QG-02 | Reference Source 原文件被未确认修改、移动或删除 | `ING-06` |
| QG-03 | Agent 未满足风险确认规则却产生写入 | `AGT-05` |
| QG-04 | 可逆写操作无法恢复到操作前事实状态 | `AGT-04` |
| QG-05 | 重试产生重复文件、链接、关系或动作 | `AGT-07` |
| QG-06 | 密钥、私人正文、绝对路径或身份信息进入公开日志/遥测/导出 | F-10、SEC 套件 |
| QG-07 | 迁移或回滚导致 v1.x 原文改变、目标事实重复或新增数据静默丢失 | MIG 套件 |
| QG-08 | 事实关系没有类型、方向、来源或可回跳证据却作为正式边展示 | `KR-07`、`GRA-01` |
| QG-09 | 无证据回答伪造来源，或 Citation 指向错误文档版本/位置 | `RET-03`、`RET-04` |
| QG-10 | 删除语义从“清索引/移除来源/删托管副本”静默升级为删除原文件 | F-10、SEC 套件 |

## 5. 测试层级

| 层级 | 目标 | 代表内容 | 默认频率 |
|---|---|---|---|
| L0 静态与契约 | 阻止类型、schema、迁移和依赖边界漂移 | lint、typecheck、JSON/schema、API/事件/工具契约、文档链接 | 每次提交 |
| L1 单元 | 验证确定性业务规则 | ID、路径、指纹、锚点、状态机、权限、风险、幂等、排名公式 | 每次提交 |
| L2 组件/服务集成 | 验证模块边界和真实本地存储 | Parser→SQLite、Job→Projection、Link→Backlink、Policy→Tool | 每次提交；慢组可分离 |
| L3 API/前端组件 | 验证对外行为和关键 UI 状态 | API 错误契约、范围标签、部分失败、差异、撤销、键盘状态 | 主分支 |
| L4 端到端 | 验证用户闭环 | 建空间→导入→查询→打开证据→保存成果；Agent 审批/撤销 | 主分支与候选版本 |
| L5 质量评测 | 验证检索、引用、关系和模型输出 | qrels、拒答、锚点、图谱证据、Agent 计划理解 | 里程碑候选 |
| L6 非功能与故障注入 | 验证规模、重启、安全、迁移和可访问性 | P50/P95、磁盘/权限/模型失败、WCAG、回滚 | 里程碑候选/发布 |
| L7 外部任务验证 | 验证自助成功和持续价值（E1） | WVKL、三类任务、4 周留存、付费/拒绝 | 阶段评审 |

L0～L6 主要产生 E2 证据；L7 产生 E1 证据。原型评审属于 E4。

### 7.1 环境级别

| 环境 | 数据 | 外部网络 | 用途 |

- 发布前补充 Firefox 与 Edge 当前稳定版的关键流程；

- 桌面完整管理和移动核心查询/阅读分别验收，不要求移动端承载完整大图谱与批量管理。

## 8. 冻结数据集与夹具契约

具体目录、manifest、标注和隐私规则见 [v2 夹具规范](fixtures/v2/README.md)。数据集至少包含：

- 两个空间中同名、近义和冲突内容，用于范围隔离；
- Markdown/TXT/可选中文本 PDF 的标题、段落、表格/代码、页码和版本变化；
- 中文路径、英文路径、空格、Unicode、超长名、相对链接和失效链接；
- 相同内容、内容更新、同名不同内容和疑似移动；
- 精确术语、同义改写、跨文档综合、无答案、相似干扰和中英混合查询；
- 显式 Link、Backlink、结构边、确认 Relation、Suggestion、Conflict 和 Relation Evidence；
- Agent R0～R3、部分拒绝、版本过期、提示注入、越权目标、重试和撤销；
- v1.x 单目录/旧 chunk/浏览器历史的合成迁移快照；
- 可确定生成的 S/M/L 规模数据，不依赖私人真实正文。

每个冻结版本必须记录：`dataset_version`、schema/parser/index/model 版本、样本哈希、授权类别、期望对象数、qrels/锚点/边标注版本和已知限制。

## 9. 格式能力验收

每个格式单独报告以下七级，不允许用单一“支持/不支持”字段替代：

| 能力 | 断言 |
|---|---|
| Discover | 授权根内正确发现；忽略越界、临时和不支持文件 |
| Extract | 文本/结构提取无静默 P0 丢失；错误有分类 |
| Browse | 阅读器能呈现可理解内容与降级说明 |
| Search | 可进入全文/向量检索，元数据过滤正确 |
| Anchor | Citation 打开到正确版本和具体位置 |
| Update | 重导入能识别相同、更新、冲突和移动，不重复创建 |
| Open source | 授权后能打开正确原文件；失联时不猜测错误路径 |

M1 门禁格式是 Markdown、TXT 和最终确认范围内的可选中文本 PDF；扫描 PDF、表格和图片在进入对应里程碑前使用同一七级合同。

## 10. 检索、问答和图谱评测

### 10.1 检索

- 每条 query 明确允许 Space、禁止 Space、相关 Block 集合和相关性等级；
- 关键词、向量、混合、过滤、重排分别报告，不只报告最终最佳配置；
- 报告 Recall@5/10、MRR、nDCG@10、范围错误、空结果、P50/P95 和失败分类；
- 新方案必须与已接受基线在同一数据、设备、模型和缓存口径下比较；
- 总体提升不能掩盖精确术语、跨语言、PDF 或无答案子集显著退化。

### 10.2 有证据问答

- Answer 每个事实断言必须能映射到 Citation；
- Citation 必须打开验证 DocumentVersion + Anchor，而非只检查来源标题；
- 无答案集验证正确拒答、证据缺口和建议缩小/扩大范围；
- 冲突证据不得合并成单一确定结论；
- 外部模型与确定性检索/引用分开计分，模型波动不改变范围和锚点护栏。

### 10.3 图谱

- 结构投影验证 Space→Collection→Document→Heading→Block 层级；
- Link、Relation 和 Suggestion 使用不同状态与类型；
- 每条展示事实边验证 `type/direction/source/evidence/status`；
- 从边、反链和聚焦视图打开同一证据，结果一致；
- 大图价值用关系发现任务成功率衡量，不用节点数证明；
- Canvas/SVG 图必须提供可操作的文本关系替代视图。

## 11. Agent 测试模型

Agent 测试按“模型输出不可信、执行器确定性校验”设计：

1. 固定 Tool Registry 和 schema；
2. 生成 Plan，但测试不假设自然语言一定正确；
3. 执行器重新校验 `space_scope`、目标版本、风险、Approval、工具版本和策略；
4. Action 使用幂等键并逐项记录结果；
5. 可逆操作保存逆向动作/版本并验证撤销；
6. 审计只保留必要去敏字段；
7. 文档中的提示注入、伪授权和任意命令文本不能改变工具权限。

必须覆盖：R0 只读、R1 可逆创建、R2 批量修改、R3 外发/回收站；计划修改、批准过期、部分批准、取消、超时、重试、局部失败、目标版本变化、越权空间、Reference Source 写入和撤销失败。

## 12. 故障注入与恢复

| 故障点 | 注入方式 | 期望 |
|---|---|---|
| Source 失联/权限变化 | 在任务阶段切换可读权限或重定位 | 任务变为可理解的 retryable/blocked 状态，不丢其他成功项 |
| Parser 失败 | 损坏/不支持/超限样本 | 单文件失败，不阻塞批次；保留文件级事实 |
| SQLite/磁盘 | 模拟事务失败、空间不足 | 原 active version 保持；无半写事实 |
| FTS/Vector | 投影写失败或 generation 中断 | 事实已保存，投影可重建；旧 generation 继续可用或明确降级 |
| 外部模型 | 超时、429、无效 JSON、离线 | 不扩大范围、不伪造证据；按策略降级/重试 |
| 应用重启 | 在每个 Job checkpoint 终止进程 | running 状态恢复为安全可重试；幂等重放无重复 |
| Agent action | 执行到一半失败 | 逐项结果可复算；成功项可撤销，失败项不伪装成功 |
| 迁移 | P0～P6 每阶段中断 | v1 原文不变；可继续、重试或回滚 |

## 13. 安全与隐私测试

- 路径穿越、符号链接/junction、大小写、UNC、设备名和授权根外路径；
- API 参数、文件元数据、OCR 文本和文档内容中的提示注入；
- 跨 Space ID 猜测、对象替换、旧 Approval 重放和目标版本竞态；
- Reference/managed_copy 四类删除语义和回收站恢复；
- 密钥、令牌、绝对路径、私人正文和身份字段的日志/事件/诊断导出扫描；
- 本地模式网络请求为 0；外发模式记录服务商、目的、最小内容范围和确认；
- 备份、迁移包和错误报告不包含未授权正文或密钥；
- 任意 SQL、任意命令、永久删除和未登记工具保持不可用。

安全测试应包含属性/模糊测试和确定性攻击样本，但不能在真实用户目录执行破坏性动作。

## 14. 性能与容量

### 14.1 计时边界

- 导入：用户确认任务至文件达到 ready/failed 的逐阶段时间；
- 索引新鲜度：来源版本被接受至新内容可查询；
- 搜索：提交查询至首屏可交互结果；
- 问答：分别报告检索完成、首 token 和最终可引用回答；
- 图谱：请求聚焦视图至节点/文本关系可交互；
- Agent：分别报告计划、用户审查、执行和验证；不把等待用户时间算作系统延迟。

### 14.2 门槛

- 搜索 P95 目标 ≤2 秒；
- 图谱聚焦视图 P95 目标 ≤3 秒；
- 导入、索引和迁移先冻结参考设备/规模基线，再设不回退门槛；
- 报告 P50/P95、最大值、失败率、冷热缓存和样本数；
- 性能提升不能以降低范围校验、引用准确或安全确认换取。

## 15. 可访问性与兼容性

- 核心流程目标 WCAG 2.2 AA；
- 全键盘完成空间切换、导入确认、查询、打开证据、反链和 Agent 审批；
- 焦点顺序、可见焦点、错误关联、aria-live、对比度和 reduced motion；
- 图谱信息不只依赖颜色/画布，提供文本关系列表；
- 200% 缩放和桌面/移动视口无关键信息截断；
- 自动扫描只作初筛，关键任务必须有人工作业验证。

## 16. 自动化门禁建议

| 门禁 | 必跑 | 允许的例外 |
|---|---|---|
| 提交/PR | L0、L1、快速 L2、前端 lint/type/build、S 数据集 | 无网络；不允许已知安全失败 |
| 主分支 | 全 L2/L3、核心 L4、S 数据集质量回归 | 外部模型测试可独立非阻塞，但契约 stub 必须通过 |
| M1/M2/M3 候选 | 目标里程碑全部场景、冻结评测、M/L 性能、故障注入、迁移/回滚 | 未进入范围的格式/模板明确 skip 理由 |
| 个人版发布 | 全套 E2、三类任务 E1、可访问性、隐私、安装升级和发布证据审计 | 发布否决项无豁免 |

实现阶段建议增加独立命令：`test:unit`、`test:integration`、`test:e2e`、`test:eval`、`test:security`、`test:perf`。具体框架和 CI YAML 在技术实现任务中确定，本策略不预先承诺工具。

## 17. 测试证据与报告

每次里程碑报告至少包含：

- build/commit、schema/parser/index/model/tool 版本；
- 数据集和标注版本、样本数量、格式/任务/语言分布；
- 设备、系统、浏览器、缓存、并发和网络策略；
- 套件通过/失败/跳过数量及跳过理由；
- 指标分子、分母、P50/P95 和置信范围（适用时）；
- 失败分类、最小复现、影响对象和是否触发发布否决；
- 原文件哈希变化、跨空间泄漏、未确认写入、重复写入和撤销结果；
- E1/E2/E3/E4 证据等级；
- GO、RETRY、PIVOT、ROLLBACK 或 STOP 结论。

测试证据进入 `docs/quality/runs/<date>-<milestone>/` 或后续机器可读制品；路线图和 PRD 只链接事实，不复制运行结果。
